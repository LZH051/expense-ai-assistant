# 开发问题与 ETL 设计记录

本项目生成模拟消费数据，并通过 ETL 脚本完成异常处理、格式统一、重复数据删除和 SQLite 入库。

## 一、模拟数据生成

`src/generate_data.py` 首先生成80条正常消费记录，包含日期、类别、金额、商家和消费说明等字段。

为了测试数据清洗功能，程序额外加入6条测试数据，包括：

- 重复记录；
- 空消费类别；
- 带人民币符号的金额；
- 带千位逗号的金额；
- 不同格式的日期；
- 非法金额、非法日期和负数金额。

因此，原始 CSV 中共有86条记录。

程序使用固定随机种子，保证每次运行都能生成相同的数据，方便测试和验收。

## 二、ETL 脚本设计

ETL 脚本位于：

```text
src/etl.py
```

数据处理分为三个步骤：

### 1. 提取数据

从以下文件读取原始消费记录：

```text
data/raw_expenses.csv
```

### 2. 清洗数据

主要处理包括：

- 去除字段前后空格；
- 空类别填为“其他”；
- 删除人民币符号和金额中的逗号；
- 金额统一保留两位小数；
- 日期统一为 `YYYY-MM-DD`；
- 删除非法金额、负数金额和非法日期；
- 删除重复消费记录。

### 3. 保存数据

清洗结果保存到：

```text
data/cleaned_expenses.csv
```

然后由 `src/load_database.py` 写入：

```text
database/expense_ai.db
```

数据库使用唯一约束和 `INSERT OR IGNORE`，避免重复运行时重复入库。

## 三、清洗结果

| 处理项目 | 数量 |
|---|---:|
| 原始数据 | 86 |
| 修复空类别 | 1 |
| 删除非法金额 | 2 |
| 删除非法日期 | 1 |
| 删除重复记录 | 1 |
| 清洗后数据 | 82 |

详细结果保存在：

```text
output/cleaning_report.json
```

## 五、实际遇到的问题与解决方法

### 问题 1：金额格式不统一

- 现象：金额中存在人民币符号、千位逗号、文字和负数。
- 原因：不同数据来源可能使用不同的金额格式。
- 解决方法：删除货币符号和逗号，使用 `Decimal` 转换金额，删除非法值和负数。
- 学到的内容：金额清洗不仅需要转换类型，还要检查取值是否合法。

### 问题 2：日期格式不统一

- 现象：数据中同时存在横线、斜线和点号分隔的日期。
- 原因：不同系统导出的日期格式可能不同。
- 解决方法：依次尝试多种日期格式，成功解析后统一保存为 `YYYY-MM-DD`。
- 学到的内容：日期转换应明确支持的格式，不能直接假设所有输入完全一致。

### 问题 3：重复运行可能重复入库

- 现象：重复执行脚本可能导致同一笔消费被多次统计。
- 原因：普通 `INSERT` 不会自动判断数据是否已经存在。
- 解决方法：在 CSV 清洗阶段删除重复记录，并在 SQLite 中设置唯一约束和使用 `INSERT OR IGNORE`。
- 验证结果：第一次入库新增82条，第二次入库新增0条、跳过82条。
- 学到的内容：去重应该同时在数据清洗层和数据库层进行保护。

### 问题 4：如何设计完整的 ETL 数据处理流程

- 现象：原始消费数据中同时存在空值、金额格式异常、日期格式不统一和重复记录，无法直接写入数据库进行统计。

- 原因：模拟数据来自不同格式的输入，如果只处理其中一种异常，仍可能造成入库失败或统计结果不准确。

- 解决方法：将处理过程划分为三个阶段：

  1. **Extract（提取）**：从 `data/raw_expenses.csv` 读取86条原始记录；
  2. **Transform（转换）**：补全空类别、统一金额和日期格式、删除非法数据及重复记录；
  3. **Load（加载）**：将82条清洗数据保存到 `data/cleaned_expenses.csv`，再写入 SQLite 数据库。

  同时生成 `output/cleaning_report.json`，记录清洗前后的数据数量。

- 验证结果：原始数据86条，清洗后保留82条；第一次入库新增82条，第二次入库新增0条。

- 学到的内容：ETL 脚本需要明确区分数据提取、数据转换和数据加载，并记录每个阶段的数据数量。这样既方便定位问题，也能证明清洗和去重逻辑有效。
